# Project development workflow

Use this workflow for changes in this project.

1. Read the project's instructions and contribution guide. Check its glossary and relevant decisions when they exist.
2. Find or create an issue for the requested change. Agree on the smallest useful scope before substantial work.
3. For an interface or ownership change, identify the module boundary and record a durable design decision when needed.
4. Make the scoped change. Run the project's relevant checks and inspect the final diff.
5. Link the issue in the pull request. Report what changed, test results, and remaining limits.

For read-only questions, answer directly without starting a ticket or design process.

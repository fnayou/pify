# Reviewed memory preferences

Pify remains a bootstrap project. The private Pi package can apply locally approved Markdown preferences from a selected vault. It does not turn every vault note into an instruction or generate suggestions. Optional private Git sync is described in [private memory repository sync](memory-sync.md). Pi's own context-file loading remains separate; Pify cannot block instructions Pi already loaded natively.

`/pify-memory review <vault-relative note.md>` reads at most 4 KiB of one regular, standalone UTF-8 file and returns its exact content, scope, and review code. Only notes under `01-global/preferences/` or `02-projects/<project>/context/` are eligible for automatic use. Inbox, reference, archive, and other notes remain inactive. A project note binds to the current project's canonical path at approval time. Linked files and linked parent directories are refused.

`/pify-memory approve <note>` shows the content and scope for interactive confirmation, including that the approved text may be sent to the selected model provider on each run. Headless callers must supply `/pify-memory approve <note> <review-code>` plus the exact `memory/approval/<sha256>` Pify scope target. The target digest covers the selected vault's absolute path and the vault-relative note path, joined by a NUL byte. The review code binds the note bytes, location, scope, project path, file identity, and selected vault identity. An edit between review and approval fails. `/pify-memory revoke <note>` removes approval without changing the note. `/pify-memory snapshot` lists active and inactive approvals without returning note content.

The private registry lives at `<Pi agent directory>/pify-state/memory-approvals.json`, outside the vault and any synced memory repository. Its directory is mode `0700` and file mode `0600`. It stores hashes and path/identity metadata, not note contents. A private lock prevents concurrent approval writes; an interrupted lock stops later writes until the owner inspects and clears it. Pify applies only entries whose content hash, file identity, vault identity, path, scope, and project binding still match. Edits, moves, replacement, a different project, and a skipped or unavailable vault make entries inactive. Reapproval is explicit. Approval metadata stays on this machine; copying notes to another machine does not copy trust.

For each Pi run, the extension writes the current approved snapshot into a namespaced prompt section. Pi 1.5.2 can patch that section when approvals change. A new session after an edit receives no stale preference text; existing session history may still contain text from earlier turns. Local approval is a Pify activation gate, not an operating-system sandbox or a veto over Pi's native context files. The approval registry accepts at most 100 entries, 4 KiB per note, and 32 KiB of reviewed note bytes in total.

# Bounded local search

Pify remains a bootstrap project. Its Pi package registers `pify_search` for filename substring search and literal content search. A call names one directory through `scope` or uses the current working directory. Absolute scopes let a caller name a separate mounted volume. Results are relative to that directory and never include matches outside it.

The tool runs an installed `rg` executable without a shell. It uses `--no-config`, `--no-follow`, and `--one-file-system`, so ambient ripgrep configuration cannot widen the search, symlink targets are not traversed, and a mount nested below the named directory is skipped. Naming the mounted directory itself makes that volume the search root. Ripgrep's normal ignore rules still apply. The tool never downloads ripgrep or changes the user's files. Missing ripgrep produces an error.

Defaults are 100 results and 2000 ms. Callers may request at most 200 results and 5000 ms. The process stops when either limit is reached, and the result reports `limitReached`, `timedOut`, and `partial`. A single oversized output record stops the search with `outputLimitReached`. Content snippets are capped at 240 characters and flag `textTruncated`. These are discovery results, not a complete index. This is a Pify-mediated read-only tool, not an operating-system sandbox; Pi's built-in tools and other extensions retain their own behavior.

The executable is an external dependency, not bundled source. [ripgrep 15.1.0's upstream licence](https://github.com/BurntSushi/ripgrep/blob/15.1.0/COPYING) is MIT or Unlicense. [Pi 1.4.0's extension contract](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/extensions.md) supplies the tool registration seam. The macOS and Linux CI matrix installs ripgrep when absent, then exercises Pify's isolated Pi package and the search fixtures. Tests cover both modes, a linked mount surrogate, an explicitly named outside directory, a large directory, result limits, and a forced timeout. The actual mount boundary comes from ripgrep's `--one-file-system` option; the linked mount fixture proves the separate no-symlink rule.

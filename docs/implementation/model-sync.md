# Explicit LM Studio model sync

Pify remains a bootstrap project. The private Pi package adds `/pify-model-sync`; it never syncs at startup. This command uses an existing `providers.lmstudio` entry in the agent directory's `models.json`, with a numeric loopback `/v1` base URL (`127.0.0.1` or `[::1]`) and `api: "openai-completions"`. Pify does not install LM Studio or select a model.

Run `/pify-model-sync preview` to inspect proposed changes without writing. Run `/pify-model-sync apply` to fetch the lists again, review one ambiguous manual entry when prompted, and confirm the write in Pi's interactive UI. A headless apply requires exact `--pify-scope models.json,pify-state/model-sync.json`; an unresolved manual entry returns a structured clarification without writing.

The command reads `GET /v1/models` and `GET /api/v1/models`. It accepts only IDs observed exactly in both responses with native `type: "llm"`. A native `display_name` becomes Pi's model name only for that exact match. It does not guess reasoning, vision, context, cost, or chat behavior from a model ID. Compatible IDs without a matching native LLM stay untouched and are reported. The official APIs do not guarantee that native `key` equals the compatible ID, so a mock test proves the matching rule, not real-server compatibility. See the [source contract](../research/w4-01-model-sync-contract.md).

Pify stores exact entry identities in private `pify-state/model-sync.json`. It can add and update its own entries, or remove an owned entry absent from the server. A hand edit breaks ownership until reviewed. Existing manual entries remain unchanged; a user's one-time "Keep manual entry" choice records that exact identity to avoid repeating the prompt. Any later edit asks again. Unrelated providers and credentials remain in `models.json` unchanged as data. User settings and trusted project settings are read before removal; a saved default that points to an absent owned model remains in place and reports a conflict. Untrusted project settings are not read.

Apply writes a private pending journal before an atomic replacement of `models.json`, then commits the sidecar. A write failure restores the previous bytes. If interrupted between files, the next explicit apply reports recovery and restores the previous configuration before a new sync. Changes to models, settings, or ownership after preview stop the apply. Private state is mode `0600` under a `0700` directory. The journal may temporarily contain the previous `models.json`, including a configured key, and is never published.

Requests allow loopback HTTP(S) only, reject redirects, time out after five seconds each, and read at most 1 MiB per response. Authentication is off unless the provider sets `authHeader: true`; then the command accepts a literal key or `$ENV_NAME` reference and sends a Bearer token to loopback. It never logs the token or runs `!command` key resolvers. A configured endpoint change blocks automatic reconciliation.

Tests use only isolated Pi files and mock endpoint responses. They cover ownership, manual review, defaults in both settings layers, unrelated provider preservation, drift, authenticated requests, malformed responses, retry, and forced failure rollback. No real LM Studio sync has been validated; no server version, capability, or loaded-model claim follows from this feature.

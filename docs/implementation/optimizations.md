# Read-only optimization inventory

Pify remains a bootstrap project. `/pify-optimizations` reports known optimization entry points in the current Pi agent and project; it installs, rewrites, disables, and removes nothing. RPC receives `pify.optimizations/v1` JSON. The terminal gets a short status. Presence means a documented file or package declaration exists, not that its contents are stock, active, licensed for redistribution, or compatible. Project settings are read only after Pi grants project trust. The report includes no settings values, command output, or local file contents.

The inventory checks the documented Pi RTK hook paths (`<agent-dir>/extensions/rtk.ts` and `.pi/extensions/rtk.ts`), an `rtk` executable on `PATH`, the `npm:@caveman-ai/pi` package declaration, a Caveman skill path, and Pi's native compaction setting. It reports damaged or untrusted settings as uncertain. Caveman CLI wrapping and other non-Pi integrations are outside this detector. Pify does not claim ownership or verification of a detected file. Pi native compaction is not a separate selective context-pruning integration.

The isolated Pi 1.5.2 golden fixture compares bare Pi and Pi with Pify installed. It asserts exact command text, JSON output, warning text, exit code, and truncation/cancellation flags. The fixture passes without a Pify transform. It does not certify RTK's intentionally filtered output or Caveman's lossy compression. No compatible selective-pruning candidate with pinned source, licence, Pi 1.5.2 behavior, and recovery proof is verified here; Pify enables no new context optimizer. Future activation needs candidate-specific golden output and recovery tests before changing this gate.

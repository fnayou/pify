# Optional SearXNG URL discovery candidate

Pify remains a bootstrap project. [#168](https://github.com/fnayou/pify/issues/168) is a Wave 4 implementation candidate, not a released or generally enabled research feature. The [accepted discovery contract](../research/w4-02-searxng-contract.md) chooses one native Pi tool using SearXNG JSON REST. Pify neither installs nor manages a SearXNG server. It does not use Crawl4AI, Firecrawl, public search instances, or another search provider as fallback.

The `pify_web_search` tool is inert unless a Pi session starts with `--pify-research --pify-search-provider searxng --pify-searxng-endpoint <base-url> --pify-scope network/searxng`. A token, if the operator's ingress requires one, is read from the environment variable named by `--pify-searxng-token-env <name>`; the token itself is never a flag. Do not place a private endpoint, token, or sensitive query in a public command transcript. The tool accepts an exact query, shows its destination and full query for TUI confirmation, and refuses headless calls without approval. Safe mode also denies it. Engine-switching `!` syntax is rejected. The selected endpoint must use HTTPS with normal certificate verification, or HTTP on an explicit loopback IP. Redirects are blocked, including same-origin redirects.

The tool makes `POST /search` with form fields `q` and `format=json`. SearXNG must enable JSON in `search.formats`; a 403 is reported as `forbidden` because JSON disablement and ingress denial cannot be distinguished from that response. Search results are untrusted URL candidates. Invalid and duplicate URLs are discarded with a warning; no URL is fetched, no snippet is treated as an instruction, and no candidate becomes a citation. A supplied URL remains usable independently through the later page-retrieval work in #147.

Initial hard ceilings are three attempted requests per loaded Pi session, five retained candidates per request, one active request, ten seconds, and 256 KiB per successful response. The `--pify-searxng-max-queries`, `--pify-searxng-max-candidates`, `--pify-searxng-timeout-ms`, and `--pify-searxng-max-bytes` flags may lower those ceilings. Failed requests count. The eventual #38 research-run budget must also encompass these calls; this isolated tool cannot supply the whole research workflow.

`node --test tests/searxng-search.test.mjs` exercises a local mock HTTP service. `python3 scripts/smoke_pi_searxng.py` checks off, headless denial, and a TUI-approved candidate through isolated Pi 1.5.2 and local model/search fixtures. CI passed both on macOS and Linux.

Real-instance validation remains an owner-controlled gate for #168. Review its evidence privately before accepting this candidate. Public artifacts must not contain the endpoint, configuration, credentials, queries, or responses.

# Session-bound background jobs

Pify remains a bootstrap project. The Pi package adds `/pify-job start <shell command>`, `/pify-job list`, `/pify-job inspect <id>`, `/pify-job log <id>`, and `/pify-job stop <id>`. A job runs in the current Pi workspace with the current process environment. It uses the platform shell, so the requested command has normal shell authority. Pify's modes are not an operating-system sandbox.

Starting a job is a Pify-mediated side effect. In an interactive Pi session, Pify shows the command and workspace for confirmation. In headless use, pass the exact `--pify-scope=jobs/current-workspace` declaration; without it, start returns `clarification_required` and launches nothing. Listing, inspection, and logs are read-only. Stop only acts on a job created in the current Pi session, so it remains available for cleanup without a start grant. A new Pi session has a new job registry.

The registry keeps at most four running jobs and twenty recent job records per session. Logs stay in memory, with separate stdout and stderr tails capped at 32,768 characters each; truncation is reported. Completed jobs report exit code or signal, and failed jobs carry a message. Stop sends SIGTERM to the job's process group, then SIGKILL if the group remains after 300 ms. It returns `stop_unconfirmed` if cleanup cannot be verified. Pi's `session_shutdown` stops active jobs on normal session exit, switch, or reload; a Node process-exit handler is a final best-effort kill path. SIGKILL of Pi or an operating-system crash cannot run those handlers. A command that deliberately detaches into another process group is outside this cleanup boundary.

This uses only [Node.js v22.23.4 `child_process`](https://github.com/nodejs/node/blob/v22.23.4/doc/api/child_process.md) and the [Pi 1.4.0 extension lifecycle](https://github.com/earendil-works/pi/blob/v1.4.0/packages/coding-agent/docs/extensions.md). No third-party job runner is bundled. [Node.js v22.23.4 licence](https://github.com/nodejs/node/blob/v22.23.4/LICENSE) covers its core runtime. The isolated Pi fixture starts, lists, inspects, reads logs, and stops a job; it also closes Pi mid-job and checks that its process group is gone. Unit tests cover failure messages and idempotent shutdown on macOS and Linux.

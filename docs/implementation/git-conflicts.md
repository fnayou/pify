# Reviewed Git conflict resolution

Pify remains a bootstrap project. `/pify-conflict list` reports unmerged paths in the current Git repository. `/pify-conflict preview <file> | ours` and `... | theirs` show the proposed text diff and a review code without changing the repository. `/pify-conflict resolve <file> | ours` or `... | theirs` applies that choice to each standard conflict hunk in one file. The choice is explicit; Pify does not infer a semantic combination of both sides. Ordinary nonconflicting lines from Git's merge result remain intact.

The path is relative to the current directory and must remain inside the repository. A headless resolution requires exact `--pify-scope git/conflicts/<repo-relative-path>` authorization. In the TUI, Pify shows the bounded diff and asks for confirmation. Declining changes nothing. The command stages only the selected file. It does not run `git commit`, `git push`, merge continuation, or an arbitrary project command. Other staged files remain untouched.

Before applying, Pify requires a regular, singly linked UTF-8 text file with standard complete conflict markers and both Git sides present. It rejects binary, symlink, deletion, malformed, and oversized conflicts as `unresolvable`. It checks that no markers remain, runs Git's whitespace check against the candidate, and parses `.json` candidates as JSON. Preview diffs over 8,192 characters are refused, so the confirmation cannot hide the rest of the proposed change. The file is rechecked against its preview and unmerged index entries before writing. On success, Pify checks the staged diff and reports `projectTests: not_run`; these structural checks do not prove semantic correctness or replace the project's build and tests.

Pify writes the selected content atomically, hashes it without Git filters, and stages its blob with `git update-index`. A failed stage or validation attempts to restore the original conflict file and unmerged index entries. If concurrent edits prevent safe restoration, the result is `recovery_needed` with the affected part named. Git commands use the current repository and do not contact its remote. This is not an OS sandbox; other processes can still change the repository concurrently.

The unit fixture creates actual merge conflicts and checks selective staging, preserved nonconflicting changes, stale previews, invalid JSON, index-failure recovery, unchanged HEAD, and unchanged bare remote. The Pi 1.5.2 smoke runs list, preview, denied headless resolution, declined TUI confirmation, and scoped resolution on macOS and Linux.

# W4-01: Pi and LM Studio model-sync contract

**Status, 2026-11-14:** Research for [issue #37](https://github.com/fnayou/pify/issues/37). Pify is a bootstrap project; this note records upstream contracts, not a released sync feature. Sources are Pi **v1.5.2** and current LM Studio developer docs. No private server or credential was used.

## Verified contracts

| Concern | Upstream contract | Consequence for an explicit sync |
| --- | --- | --- |
| Pi storage | `<agent-dir>/models.json` declares compatible providers and model entries. `<agent-dir>/auth.json` holds saved credentials. Pi's `models.json` may itself contain a literal key, so treat it as sensitive. `PI_CODING_AGENT_DIR` changes the agent directory. [Pi configuration](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/configuration.md), [Pi models](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/models.md) | Keep ownership metadata in a Pify sidecar. Preserve unrelated provider fields and credentials. |
| Pi model identity | A `providers.<provider>.models[]` entry needs `id`, the value sent to the API. A matching ID replaces an existing entry for that provider. Other fields such as `reasoning`, `input`, `contextWindow`, and `maxTokens` are configuration declarations, with defaults that are not measurements. [Pi model schema](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/models-configuration.md) | Bind ownership to exact provider, ID, and entry content. Do not infer capabilities from a name or Pi default. |
| Pi defaults | `defaultProvider` and `defaultModel` live in settings. Trusted project settings override agent settings; project `.pi` configuration is skipped without trust. A session can restore a previously selected model without changing startup defaults. [Pi settings](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/settings.md), [configuration](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/configuration.md), [model selection](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/models.md), [security](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/security.md) | Resolve both settings layers before removing or renaming an owned entry. A runtime model is not proof of the saved default. |
| Pi extension seam | An extension can register an explicit command. `ctx.isProjectTrusted()` includes temporary and CLI trust decisions, so it is the relevant guard before honoring project-local settings. [Pi extensions](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/extensions.md) | Run sync only from an invoked command and use the session's actual trust state. |
| LM Studio compatible list | `GET /v1/models` lists models visible to the server. With Just-In-Time loading, it can include downloaded models that are not loaded. The official page gives the method and visibility rule but no response schema. [LM Studio compatible list](https://lmstudio.ai/docs/developer/openai-compat/models) | A listed model is not proof it is loaded or that a capability works. Validate the response shape before using IDs. |
| LM Studio native list | Native REST v1 was released with LM Studio 0.4.0. `GET /api/v1/models` returns `models[]`; each entry has `type` (`llm`, `embedding`, `decision`) and a unique `key`. Optional capability fields include `vision`, `trained_for_tool_use`, and a structured `reasoning` configuration. `max_context_length` can be null; loaded instances have their own configured `context_length`. [REST overview](https://lmstudio.ai/docs/developer/rest), [native model list](https://lmstudio.ai/docs/developer/rest/list) | Filter to `type: "llm"`. Report only fields actually returned. Model capacity and an active instance's context are different facts. |
| Authentication | LM Studio API-token authentication requires 0.4.0+. It is off by default; when enabled, requests require `Authorization: Bearer <token>`. Pi's model schema supports key resolution and an `authHeader` setting for sending the resolved key as Bearer. [LM Studio authentication](https://lmstudio.ai/docs/developer/core/authentication), [Pi model schema](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/models-configuration.md) | Keep tokens outside repo artifacts. Validate the actual authenticated request in an isolated fixture before relying on a Pi config shape. |

## Compatibility and evidence gaps

- **ID mapping is unverified.** The official `/v1/models` page does not define its JSON fields; the native endpoint uses `models[].key`. Neither page guarantees that a native `key` is the exact compatible model ID Pi must send. Reconcile only exact, independently validated IDs; otherwise omit native metadata or report a conflict. [Compatible list](https://lmstudio.ai/docs/developer/openai-compat/models), [native list](https://lmstudio.ai/docs/developer/rest/list), [Pi model schema](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/models-configuration.md)
- **A successful list request is not a version check.** LM Studio documents native REST v1 for 0.4.0+, but its [listed v1 endpoints](https://lmstudio.ai/docs/developer/rest) include no server-version or dedicated health endpoint. This is a documentation gap, not proof that no other endpoint exists. Check the native response contract and require separate version evidence when an exact version matters. `/v1/models` alone can also be served by another compatible server. [LM Studio REST overview](https://lmstudio.ai/docs/developer/rest), [compatible list](https://lmstudio.ai/docs/developer/openai-compat/models)
- **Capabilities are endpoint reports.** `capabilities.reasoning` is an object with allowed options when present, not Pi's Boolean `reasoning` field. An absent capability or null context length is unknown, not false or zero. No inference test or exact native-to-compatible ID mapping has been performed here. [LM Studio native list](https://lmstudio.ai/docs/developer/rest/list), [Pi model schema](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/models-configuration.md)
- **Sidecar format is a Pify decision.** Pi's published `models.json` schema does not define a Pify ownership marker. The earlier [W0-04 proposal](w0-04-provider-model-storage.md) is not a compatibility guarantee. Test sidecar identity, drift, manual-entry collisions, default preservation, and multi-file failure recovery in isolated agents before accepting sync. [Pi model schema](https://github.com/earendil-works/pi/blob/v1.5.2/packages/coding-agent/docs/models-configuration.md), [issue #37](https://github.com/fnayou/pify/issues/37)

**Practical gate:** A mock server should serve both endpoint shapes and an authenticated variant. A separately authorized live check can then establish actual ID correspondence, version, and capability claims without publishing endpoint details or credentials. [Issue #37](https://github.com/fnayou/pify/issues/37)
